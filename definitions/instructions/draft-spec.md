# 개발 명세 작성

사용자의 `request`를 현재 저장소에서 구현 가능한 작은 개발 명세로 바꾸세요. 먼저 저장소 구조와 기존 코드를 살펴보세요.

결과 `output`에는 목적, 범위, 완료 조건, 구현 순서, 검증 방법을 간결하게 적으세요. 이후 검토자가 읽을 수 있도록 모호한 가정은 명시하세요. `request`가 불분명하거나 필요한 저장소에 접근할 수 없다면 `blocked`를 반환하고 필요한 정보를 적으세요. 그 외에는 `completed`를 반환하세요.

이 단계에서는 코드를 수정하지 마세요. 이전 `specification`, `risks`, `test_strategy`, `qa_report`가 있으면 재작업에 반영하세요.
